# walletspace

Локальный сервис для Tron-кошельков, выведенных из **одной** мнемоники и пасфразы (BIP39/BIP44, путь `m/44'/195'/0'/0/{index}`).
При запуске открывает веб-UI со списком кошельков, их балансами в TRX и USDT, кнопкой «сгенерировать новый» и формой отправки.

Приватные ключи **не хранятся на диске**: в `data/wallets.json` лежат только индексы деривации, адреса и метки. Ключ выводится из мнемоники в момент подписи транзакции.

## Запуск

```bash
# мнемоника сгенерируется в ./data/mnemonic.txt при первом запуске
go run ./cmd/walletspace

# или со своей мнемоникой
MNEMONIC="слова ..." PASSPHRASE="" go run ./cmd/walletspace
```

UI откроется на http://127.0.0.1:8080 автоматически.

## Конфигурация

Значения берутся из `./config.yaml` (необязателен), затем из переменных окружения — окружение приоритетнее. Шаблон: [config.yaml.example](config.yaml.example).

| Переменная         | По умолчанию     | Что делает                                                 |
| ------------------ | ---------------- | ---------------------------------------------------------- |
| `ADDR`             | `127.0.0.1:8080` | адрес прослушивания                                        |
| `DATA_DIR`         | `./data`         | где лежат `wallets.json` и `mnemonic.txt`                  |
| `OPEN_BROWSER`     | `true`           | открывать браузер при старте                               |
| `MNEMONIC`         | —                | пусто → генерируется и пишется в `{DATA_DIR}/mnemonic.txt` |
| `PASSPHRASE`       | —                | пасфраза BIP39                                             |
| `NETWORK`          | `mainnet`        | `mainnet` или `nile`                                       |
| `NODES`            | —                | пусто → дефолтные ноды сети (см. ниже)                     |
| `TRON_PRO_API_KEY` | —                | ключ TronGrid, снимает лимиты публичных нод                |
| `USDT_CONTRACT`    | —                | пусто → дефолтный контракт сети                            |
| `FEE_LIMIT_TRX`    | `50`             | лимит комиссии для TRC20-переводов                         |

Формат `NODES` — список через запятую, `scheme://host[:port][|tier]`. Схемы: `grpc`, `grpcs` (TLS), `http`, `https`. Тир 0 — основной, выше — резерв, используется только когда все ноды младших тиров недоступны:

```
NODES="grpcs://grpc.trongrid.io:50051,https://api.trongrid.io,https://tron-rpc.publicnode.com|1"
```

Дефолты по сетям:

- **mainnet** — USDT `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`, ноды TronGrid (tier 0) и PublicNode (tier 1)
- **nile** — USDT `TXLAQ63Xg1NAzckPwKHvzw7CSEmLMEqcdj`, ноды `grpc.nile.trongrid.io:50051` и `https://nile.trongrid.io`

Символ и число знаков токена читаются из контракта на старте и пишутся в лог — это же и проверка, что контракт задан правильно.

## Безопасность

- **Мнемоника — единственный способ восстановить средства.** Файл `data/mnemonic.txt` создаётся с правами `0600`; забэкапьте его.
- **Пасфразу нельзя менять после создания кошельков** — адреса станут другими. Сервис хранит в `wallets.json` контрольный адрес нулевого индекса и откажется стартовать при несовпадении. Файл без этого адреса тоже отклоняется.
- **API не имеет аутентификации**: кто дотянулся до порта — тот отправляет средства. Держите `ADDR` на `127.0.0.1`, не выставляйте наружу.
- От запросов, которые чужая веб-страница делает через браузер пользователя, стоит защита: проверяются `Sec-Fetch-Site` и `Origin`, а изменяющие запросы обязаны иметь `Content-Type: application/json` — из-за этого браузер вынужден слать preflight, который не проходит. Тело запроса ограничено 64 КБ — кроме деплоя контракта, где байткод едет в hex и лимит поднят до 512 КБ.
- `data/`, `config.yaml` и `.env` добавлены в `.gitignore`.

## API

| Метод   | Путь                                   | Назначение                                                                                   |
| ------- | -------------------------------------- | -------------------------------------------------------------------------------------------- |
| `GET`   | `/api/info`                            | сеть, обозреватель, контракт и децималы токена                                               |
| `GET`   | `/api/wallets`                         | список кошельков                                                                             |
| `POST`  | `/api/wallets`                         | создать следующий индекс, тело `{"label":"..."}`                                             |
| `PATCH` | `/api/wallets/{index}`                 | переименовать                                                                                |
| `GET`   | `/api/balances`                        | балансы всех кошельков; `?refresh=1` минует кеш (TTL 15с)                                    |
| `POST`  | `/api/wallets/{index}/estimate`        | во что обойдётся перевод; тело как у `/send`                                                 |
| `POST`  | `/api/wallets/{index}/send`            | `{"asset":"trx"\|"usdt","to":"T...","amount":"1.5"}` → `{"txid":"..."}`                      |
| `GET`   | `/api/wallets/{index}/resources`       | стейк, пулы bandwidth и energy, разморозки, делегации                                        |
| `POST`  | `/api/wallets/{index}/stake`           | `{"resource":"bandwidth"\|"energy","amount":"100"}` — сумма в TRX                            |
| `POST`  | `/api/wallets/{index}/unstake`         | то же тело; TRX уходит в разморозку на 14 дней                                               |
| `POST`  | `/api/wallets/{index}/delegate`        | `{"resource":...,"amount":"1000","to":"T..."}` — количество в единицах ресурса               |
| `POST`  | `/api/wallets/{index}/reclaim`         | то же тело, забирает делегацию обратно                                                       |
| `POST`  | `/api/wallets/{index}/withdraw`        | забрать размороженное, без тела                                                              |
| `POST`  | `/api/wallets/{index}/cancel-unstakes` | отменить все разморозки, без тела                                                            |
| `POST`  | `/api/wallets/{index}/deploy-estimate` | сколько будет стоить деплой; тело то же, ничего не подписывается                             |
| `POST`  | `/api/wallets/{index}/deploy`          | деплой контракта, тело ниже → `{"txid","address","confirmed","failure","energy_used","fee"}` |

Изменяющие запросы (`POST`, `PATCH`) требуют заголовок `Content-Type: application/json`. Ошибки ввода возвращают `400`, отказ ноды — `502`.

Вместо суммы можно передать `"max"`: у `/estimate` и `/send` это «отправить всё, что останется после комиссии» — сервер считает остаток сам, в decimal, потому что только он знает, что примет нода. У `/reclaim` это «забрать делегацию целиком»: показанное количество ресурса получено конвертацией из TRX и обратно конвертируется с округлением вверх, мимо того, что реально делегировано.

### Деплой контракта

```json
{
  "name": "Token",
  "abi": "[…]",
  "bytecode": "0x6080…",
  "constructor_params": "[{\"uint256\":\"1000\"}]",
  "fee_limit": "1000",
  "consume_user_resource_percent": 100,
  "origin_energy_limit": 10000000
}
```

`abi` и `constructor_params` необязательны, `fee_limit` в TRX и обязан быть больше нуля: без него нода подставит свой потолок, который заметно ниже стоимости деплоя, и транзакция умрёт на полпути с уже списанной комиссией. Ответ ждёт квитанцию до 24 секунд; `confirmed: false` значит, что она не пришла, а не что что-то сломалось. `failure` — вердикт VM (`OUT_OF_ENERGY`, `REVERT: …`) для транзакции, которая прошла, но контракта не создала; ответ всё равно `200`, потому что комиссия списана и txid нужен.

### Оценка

`deploy-estimate` принимает то же тело и отвечает `{"energy","bandwidth","fee","min_fee_limit","shortfall"}`. Нода собирает транзакцию и прогоняет конструктор, ничего не подписывая и не отправляя, — конструктор, который ревертит, отваливается здесь и бесплатно.

`fee` и `min_fee_limit` — разные числа. `fee` это TRX, которые реально спишутся: то, что не покрыл собственный стейк отправителя, у аккаунта с запасом энергии там ноль. `min_fee_limit` — минимальный лимит комиссии: он ограничивает энергию, которую транзакции вообще позволено сжечь, поэтому обязан покрывать её целиком, включая ту, что приходит из стейка бесплатно.
